## Findings and verdicts

### F5-01 [stage-1/2, medium] Built CSS is rebuilt as HTML, so off-site `url()` and `@import` are missed: **Fix now** (T31)

`src/lib/offsite-requests.ts:116-154` (tag rebuild; separators dropped at `:127`) and `:198-208` (the `url()` and
`@import` scans read only the rebuilt text). `tests/build.test.ts:173-176` sends every built `.css` through this path.
This touches the spec §6 NFR. It is a regression from T29.

Every `<` followed by a letter starts a "tag", and its text up to the next `>` outside quotes is rebuilt with `/`
removed. lightningcss minifies `@media (40rem < width < 60rem)` to `(40rem<width<60rem)`, which has that shape. In a
scratch build, a hand-written range query plus an off-site `background:url(https://cdn.example.com/hero.jpg)` in
`global.css` (over the 4 KB inline limit) produced a `dist/_astro/*.css` for which the guard returned `[]`.

### F5-02 [stage-1, medium] A raw `>` in an earlier attribute hides `<link>`/`<image>`/`<use>` `href`: **Fix now** (T31)

`src/lib/offsite-requests.ts:181` (`/<link\s([^>]*)>/gi`), `:187` (`/<(?:image|use)\s([^>]*)>/gi`), and `attr()` at
`:68-70`, which requires whitespace before the name. These are unchanged since T17, and the bug is older than T29.
This touches the spec §6 NFR. The finding contradicts the comment at `:94-96` and `sad.md:744, 818`.

Astro 7 keeps `>` raw in expression attributes, as it does `<`. Both reviewers confirmed in a scratch build:
`<link title={t} rel="stylesheet" href="https://c.example.com/x.css">` with `t = "Jane > PI"` builds to a page that
the guard passes. The same happens for `<svg><image title={t} href=…/></svg>` and Markdown raw HTML. The `/`-separator
forms (`<img/src=…>`, `<link/rel=…/href=…>`, `<image/href=…>`) are also missed, but only hand-written markup produces them.

### F5-03 [stage-2, low] `<link>` and `<image>`/`<use>` scans are quadratic: **Fix now** (T31)

`:181, :187`. This is the class of R4-07, which was fixed only for `url()`. Measured: `"<link ".repeat(…)`
took 0.99 s at 100 KB and 3.96 s at 200 KB, and was killed at 20 s for 1 MB. `<use ` and `<image ` behave the same.
The effect is a hung build, never a visitor problem.

### F5-04 [stage-1/2, low] The tag reader ends regions in different places from the browser: **Fix now** (T31)

`:75-85, 111-119, 162-168, 202`. This touches the spec §6 NFR. Most cases are regressions against T27.
In each case below, a later `<div style="background:url(&quot;https://x.example.com/a&quot;)">` returns `[]`, but the
browser fetches it:

- **`<noscript>`:** it is in `RAW_TEXT`. A visitor with scripting off parses it as markup.
- **Comments:** `<!-->`, `<!--->` and `--!>` end a comment in the browser. The guard waits for `-->`.
- **Bogus comments:** `<![CDATA[ … ]]>` outside SVG, and `</` followed by a non-letter.
- **CDATA inside SVG.**
- **End tags:** `indexOf("</script")` also matches `</scripts`.
- **SVG `<style>`:** one with no `</style>` stops the decode for the rest of the page.

An escaped `(` in an unquoted `url()` (`url(https://ep.example.com/a\(b)`) is also missed. All of these come only from
hand-written markup or raw HTML in Markdown.

### F5-05 [stage-2, low] Miss-causing mutants survive; one comment is wrong: **Fix now** (T31)

In a run of 47 mutants, these survivors hide a real request:

- **Whitespace around `=`:** dropping the skip before `=` (`:134`) or after it (`:137`).
- **SVG depth:** dropping the `Math.max(0, …)` clamp on `svgDepth` (`:157`).
- **Raw-text end:** searching `html` instead of `lower` for the end tag (`:167`).
- **`RAW_TEXT`:** removing any entry other than `script`/`style`.
- **Head slice:** narrowing it at `:116`.

The R3/R4 records list "odd whitespace around `=`" as sound, but no test locks it in. The comment at `:74` says that
raw-text elements are read "as written", but `title` and `textarea` are RCDATA, which the browser does decode. This
touches the CLAUDE.md rule that each `src/lib` helper is tested.
