## Findings and verdicts

### F7-01 [stage-2, medium] Four whole-page readings don't cover a page that needs different readings in different places: **Fix now** (T34)

`src/lib/offsite-requests.ts:250-261` (union), `:223-238` (regions), `:216-220`, `:160`. Each reading is applied to the
whole page, so the comment at `:250-251` ("can only hide a request from itself") is false when all four lose sync. Verified
against parse5 and reported by pre-T31 but missed at HEAD (150k-input fuzz: 133 misses, 122 reported by pre-T31):

- `<svg><title><script>x='<span title="';</script><img src="https://t.example.com/p.png"></title></svg>`
- `<svg><style><img src="https://t.example.com/p.png"></style></svg>`
- `<svg><style><!-- </style><a title=" --></style></svg><img …>` and the CDATA form (stage 1 found this independently)
- `<svg></math><script><img src=…></script></svg>`: `svgDepth` is shared by `<svg>` and `<math>`, so a stray `</math>`
  closes an SVG; pre-T33 reported it, so the result is no longer additive
- a tag name of 64+ characters (`html.slice(i, i + 64)` at `:160`)

No realistic Astro shape triggers these; a scratch Astro 7.3.5 build and the current `dist/` are clean. Fix: a fifth,
region-free tag pass unioned with the four readings; separate svg/math counters; sticky head regex without a length limit;
correct the comment and the spec §8 wording. Spec §8 R6-02 is reopened.
