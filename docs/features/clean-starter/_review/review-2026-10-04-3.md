## Findings and verdicts

### F-1 [stage-1, medium] AC-13b is missing from `ux-flows.md`: **Fix now** (T28)

`ux-flows.md:147-182`, coverage table `:203-223`; AC-13, AC-13b. The US-06 flowchart sends every
unknown file to "Left in place and reported", with no `layout-clash` stop, and there is no AC-13b row.
T26's `files_hint` left out ux-flows. Anyone building SCR-04 or its tests from ux-flows would leave
out the stop message.

### F-2 [stage-1, low] Off-site check misses encoded `url()` outside `style`: **Fix now** (T27)

`src/lib/offsite-requests.ts:75-79`; spec §6 NFR (third-party requests 0). In a scratch Astro 7
build, `mask={'url("https://m.example.com/m.svg#m")'}` builds to `mask="url(&quot;…&quot;)"`, and
`filter` does the same. The guard returns `[]`. A `<style>` inside an inline `<svg>` is foreign
content, so the browser decodes its entities too, and the guard misses that as well. Nothing on the
site uses these today.

### F-3 [stage-1, low] AC-13b's scope is narrower than the code: **Fix now** (T28)

spec AC-13b ("unknown or protected") and data-model `:204-205` ("protected, owned or unknown")
differ from `deploy/plan.ts:356-366, 401-407`. The code stops on any listed path, including owned and
approved ones (`tests/plan.test.ts:484-497` covers owned). The code is the safe behaviour, so the
docs are widened to match it.

### F-4 [stage-1, low] AC-13b → task traceability: **Fix now** (T28)

`tasks.json` T16 (`acs: ["AC-11","AC-13"]`) holds the `layout-clash` code. The only task tagged
AC-13b is the docs task T26. Commit `04b4222` (T24 code) has no `SDD-Task: T24` trailer. This is
noted in the task file; history is not rewritten.

### R3-01 [stage-2, low] Decoder needs `;` and knows five named entities: **Fix now** (T27)

`src/lib/offsite-requests.ts:31`. `url(&#34https://d.example.com/x&#34)` and
`url(&quot;https&colon;&sol;&sol;e.example.com/x&quot;)` both return `[]`, but browsers fetch them.

### R3-02 [stage-2, low] Unquoted `style` values not decoded: **Fix now** (T27)

`src/lib/offsite-requests.ts:76`. `<div style=background:url(&quot;https://c.example.com/x&quot;)>`
returns `[]`. The shared attribute pattern at `:43` handles unquoted values, but the style pass
does not.

### R3-03 [stage-2, low] Style pattern also matches inside `<script>` and comments: **Not an issue**

`src/lib/offsite-requests.ts:76`. The failure is a false positive, so the build fails rather than
the visitor being affected. The site has no client JS (CLAUDE.md "No runtime"). Revisit if client JS
arrives.

### R3-04 [stage-2, low] Two decode branches have no test: **Fix now** (T27)

`tests/offsite-requests.test.ts:58-93`. No case uses a single-quoted `style` or a hex entity, so
deleting the `'([^']*)'` branch (`offsite-requests.ts:76`) or the `#x` branch (`:31`) still passes.

### R3-05 [stage-2, low] Fixture build shares the repo's caches: **Defer** (§8)

`tests/build.test.ts:123, 136`. The `node_modules` symlink means the fixture build writes to the
real `node_modules/.astro` and `.vite` caches. This is harmless today: the content is identical and
the builds run one after another. A concurrent `npm run build`, or a later fixture with different
content, could rewrite `data-store.json`. Recorded in spec §8, due 2026-10-31.
