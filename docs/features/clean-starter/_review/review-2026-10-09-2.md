## Findings and verdicts

### J10-01 [stage-1 + stage-2, medium, not realistic] The legacy scan is quadratic after non-HTML whitespace and loses `src` behind an NBSP: **Fix now** (T40)

`src/lib/offsite-requests.ts:418` (`attrPattern`, `(?:^|\s)`), `:425-433` (`followsAttribute`), `spec.md:244`. The regex starts a match at any
`\s`, including NBSP, `\v` and U+3000; `followsAttribute` walks back over HTML whitespace only, so each match rescans the run back to
the last HTML whitespace. `legacyUrls` on `" src=x".repeat(n)`: 60 KB 5.1 s, 120 KB 20.3 s (pre-T38 1 ms), tens of minutes at 1 MB, which
would hang the build test that gates publishing, and falsifies "every scan is linear". The same mismatch rejects
`<img alt="a > b"` + NBSP + ` src="…"` (a quote ends up inside the token), which pre-T31 and pre-T38 reported and parse5 fetches (the only
class lost to pre-T31 across 320k fuzz inputs). Needs thousands of NBSP-prefixed `src=` or a misread page; not Astro output. A regression introduced by T38.

### J10-02 [stage-2, low, not realistic] A rejected candidate still uses up its value: **Fix now** (T40)

`src/lib/offsite-requests.ts:418-419, :438-439`. `matchAll` consumes `src=VALUE` of every candidate, including ones `followsAttribute` rejects,
so a stray `src='` inside a quoted value of the other quote type eats the real attribute:
`<svg><style><img alt='a > src="b' src="https://t.example.com/p.png"></style></svg>` returns `[]`; pre-T38 reports it. Fix: value in a lookahead
(measured linear at 4 MB).

### J10-03 [stage-1 + stage-2, low] Comment and spec claims are stronger than the code: **Fix now** (T40, T41)

`src/lib/offsite-requests.ts:5-13, :405-415`, `spec.md:244`. The header says the scan is over-eager "so that no misreading of the page can hide a
request" (its own last line and J10-01/J10-02 contradict that). "Additive to the pre-T31 scan except for the residuals" omits a `/` separator and
an unquoted value holding `&`, `;` or a quote before `src` (2 in 100k fuzz inputs; pre-T31 caught them). The header omits the false-positive class
T38 added, a word or boolean attribute before `src=` in page text or inline code (`<iframe hidden src="https://…">`,
`<video controls poster=…>`, `<img loading=lazy src=https://…>` in Markdown inline code), confirmed new since T38 by a scratch Astro build
(Markdown prose and Shiki blocks are safe). Not blocking: spec §8 and the build test message name the cases.

### J10-04 [stage-1 + stage-2, low] Six mutants survive; one test row pins a request nobody makes: **Fix now** (T40)

`tests/offsite-requests.test.ts` T38 block (~:905-985, `:922`). 7 of 33 mutants survive (one equivalent); six hide a fetched request: `/` in the
forbidden set, token boundary only at a space, tokens capped at 16 characters, scan flag `gi` → `g`, `attrPattern` flag `i` → none, no `\s*`
before `=`. The "a bare controls and poster" row uses `<svg><style><video …>`; `<video>` stays in the SVG namespace and parse5 fetches nothing
(the flaw H9-02 fixed for `<link>`).
